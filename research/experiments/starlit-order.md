# Does a cold article sample predict the benefit of STARLIT ordering?

Preregistered before measuring the two arms. Use [Margaritov’s published AMD package recipe](https://github.com/amargaritov/starlit/tree/14d68047e7b89f81c4504dc05f8e57a96247d880), unchanged executable and dictionary. ON embeds the published similarity order. OFF embeds one line `0`: upstream appends all unlisted page indices in original order, so this is the identity permutation. Charge each arm for its actual compressed order file. Published AMD comparison is compressor 390,308 + archive 114,904,928; the official Intel total is different. Reproducing the AMD port is not a new record. Earlier preflight with the fx2-cmix archive's unpacked engine exited with illegal instruction on this host; use the documented AMD-native winner rather than emulating that build.

Select complete pages wholly within five fixed 1 MiB raw windows at offsets 0, 250000000, 500000000, 750000000 and 998951424. Compare exactly the same pages per window in original versus restricted global order. Compress cold with STARLIT's generic dictionary-assisted coding path; verify decoded streams. These proxies omit full PHDA9 preprocessing, have short contexts, and cannot place similar pages from different windows next to each other. They are deliberately fallible. Preregister predicted full saving = one billion times pooled (OFF−ON) payload bytes / pooled raw page bytes, plus measured OFF−ON compressor package size. Positive means ordering wins. Report signed error and whether the sign agrees; one ablation cannot establish general predictive reliability.

Then run each packaged encoder on all of enwik9, decode each archive in a fresh directory without the original corpus, and compare every byte. Score S1+S2. Report phase elapsed seconds and GNU time peak RSS (not simultaneous summed RSS), sample directory disk footprints, single-core affinity, hashes and comparison to the published AMD figures. No Geekbench calibration or official resource ruling. Four full phases may take days; run sequentially. Keep diagnostics even on failure; only verified phases count. Do not publish corpus or executable artifacts.
